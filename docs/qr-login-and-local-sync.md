# 原生扫码登录与局域网同步

## 行为

- 哔哩哔哩、斗鱼和虎牙在 App 与电视端共用原生扫码页，账号管理将扫码登录放在首位。手机确认后自动获取凭据，交给现有账号管理器安全保存并向平台验证身份。
- 抖音按用户选择保留现有网页登录，扫码及额外身份验证均在官方页面完成，然后点击“完成登录”。移除抖音独立扫码入口和直接 HTTP 实现。电视端通过手机或电脑上的 Simple Live 登录后加密配对接收账号；不支持内嵌网页登录的系统仍可配对接收或导入 Cookie。
- 扫描、手机确认、账号验证是三个不同阶段。只有账号接口验证成功才显示“已验证登录”。平台验证失败时保留实际状态，不把二维码授权成功当作身份验证成功。
- 二维码过期或被取消后支持刷新。刷新、离开页面会关闭旧请求；旧二维码的迟到响应不能保存账号。轮询不会重叠。
- App 同步页优先提供“连接同一 Wi-Fi 下的设备”。设备列表、扫描二维码、手动地址三种方式均直接连接目标设备。
- 支持旧版二维码中的多个网卡地址，选择后立即连接；保留手动输入的端口。IPv6 地址通过 `Uri` 构造请求。
- 电视端进入同步页不再自动创建远程房间；局域网二维码独立可用。只有远程房间真正创建成功才显示房间二维码。
- 向电视发送关注列表时跳过电视不支持的标签接口。账号同步入口改为账号管理中的加密配对。
- 接收覆盖数据时，先解析全部条目再清空旧数据，避免格式损坏导致先删除旧列表。设备发现改为 UTF-8 编解码，忽略无效广播，处理启动尚未完成和监听失败。

## 远程房间故障证据

2026-10-16 使用项目原有 `signalr_netcore` 客户端实测 `https://sync1.nsapps.cn/sync`：连接成功，调用 `CreateRoom("Simple Live", "windows", "1.11.11")` 时服务器返回：

```
An unexpected error occurred invoking 'CreateRoom' on the server.
```

上游同版本请求代码与本项目相同。客户端无法修复第三方服务器内部异常，也没有该服务器的异常堆栈，不能进一步断言其内部根因。失败页面现在保留原因、重试及局域网/WebDAV 入口。调用有超时；关闭或替换连接后不再向已关闭的流发送事件。自部署服务可在构建时通过 `--dart-define=SYNC_SERVER_URL=https://.../sync` 指定，必须兼容原有 SignalR 协议。

## 官方扫码协议与隔离

三个原生扫码平台的实现位于 `simple_live_account/lib/src/qr_login.dart`、`qr_login_http.dart` 和 `widgets/platform_qr_login_page.dart`，不需要执行登录网页或初始化 WebView。抖音继续使用现有的 `PlatformWebLoginPage`。

| 平台 | 官方生成/轮询接口 | 授权完成 |
| --- | --- | --- |
| 哔哩哔哩 | `passport.bilibili.com/x/passport-login/web/qrcode/generate`、`poll` | 收集官方响应 Cookie，再验证账号 |
| 斗鱼 | `passport.douyu.com/scan/generateCode`、`japi/scan/auth` | 调用官方返回的 JSONP 登录回调，再验证账号 |
| 虎牙 | `udblgn.huya.com/qrLgn/getQrId`、`tryQrLogin` | 完成官方 Cookie/`l.huya.com` 网站登录回调，再验证账号 |

每次二维码创建独立的内存 Cookie 容器，不加载已有账号。请求和重定向只允许对应平台已列出的 HTTPS 主机，拒绝非默认端口和带用户信息的地址；Cookie 按域名、路径、安全标记和有效期发送。回调不执行 JavaScript，只解析 JSON/固定名称 JSONP。响应和授权 URL 不记录到日志。

协议依据为 2026-10-16 读取的官方页面和公开脚本：

- 斗鱼：`https://shark.douyucdn.cn/app/douyu-passport/js/page/login/app-all.js?v=v202510276`
- 虎牙：`https://udbres.huya.com/js/HyUDBWebSDK-w1.0.js` 与官网 `headerfunction_9d8ec734.js`
- 抖音：官网 `client-entry~1.28f20eec.js` 与 `chunks/1426.e40b67d9.js` 中的账号 SDK。

## 验证边界

- 真实匿名请求已确认哔哩哔哩、斗鱼、虎牙能够生成二维码并进入等待扫码；虎牙返回的图片可解码为 300 × 300。
- 抖音直接 HTTP 试验在匿名访问官网初始化前后均返回官方拒绝码 4031，未取得二维码或轮询令牌；该实现已移除，不再作为产品登录路径。
- 官方浏览器组件能生成二维码并轮询，但两次无界面浏览器试验均被手机立即提示过期；已核对二维码图片内容和官方短链跳转一致。用户随后报告普通浏览器无痕窗口的官网二维码可确认登录。有界面测试浏览器也获得用户扫码确认，但官方返回 2046 并要求短信身份验证。等待超时后仍未收到账号凭据，未进行账号验证；临时浏览器及配置目录已清理。
- 根据用户决定，停止独立扫码方案试验并保留现有网页登录。官方组件提取二维码的方案未接入 Flutter，也没有把本次手机确认记录为完整登录验收通过。上述环境对比尚不能单独确定拒绝的全部根因。
- 2026-10-16（America/Los_Angeles），用户用斗鱼手机 App 扫描新逻辑生成的二维码并确认。实际 `OfficialQrLoginSession('douyu')` 返回 `confirmed`，完成官方回调后使用本次取得的凭据调用账号验证，结果为 `verified` 且存在有效身份。
- 虎牙也已通过手机扫码实测：官方轮询返回 stage 2，该响应直接取得可用凭据，随后账号接口验证为 `verified` 且存在有效身份；本次没有收到可选的 `domainUrlList`、`loginTime` 和 `sign`，因此不能把本次成功视为这些可选回调分支的线上验证。
- 哔哩哔哩已通过手机扫码实测：新扫码会话返回 `confirmed`，随后官方账号接口验证为 `verified` 且存在有效身份。三个成功平台均未加载已有账号，测试凭据仅留在内存，未导入已安装 App。
- 新测试覆盖 Cookie 隔离、官方回调限制、扫码状态、刷新/关闭丢弃迟到结果、登录验证失败、同步超时及重试、旧连接事件隔离、局域网真实回环 HTTP 收发、损坏数据覆盖保护、电视标签兼容和默认局域网页面。
- HTTP 收发测试只使用隔离数据库和合成数据；不等同于用户电脑、手机、电视之间的实机网络验收。本次没有修改第三方同步服务器，也未发布新安装包。
